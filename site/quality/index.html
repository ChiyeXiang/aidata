01

Expert qualification & originality

Authors pass domain challenges and rule tests; STEM tasks also receive similarity and searchability screening.

02

Task validity

Independent checks confirm complete conditions, answer uniqueness, reproducible environments and score discrimination.

03

Source, derivation & runtime evidence

Professional claims retain sources; scientific tasks retain derivations; agent and code work retains traces, logs, patches and tests.

04

Author–verifier separation

Task authoring, reference resolution, verification engineering and adjudication remain distinct responsibilities.

05

Blind review & expert adjudication

Disputes are re-reviewed without exposing the original judgment, with evidence, version and ruling documented.

06

Version & contamination control

Tasks, data, environments, verifiers and model feedback are versioned, with leakage risks managed per project.

Four-stage review of complex AI work

Review not only the answer, but the task, process and reliability of the original evaluation.

01

Input quality

Whether instructions, environment and task are understandable, executable and evaluable.

02

Process & trajectory

Whether planning, tool use, iteration and self-check are reasonable.

03

Output quality

Whether the result is complete, accurate, professional and usable.

04

Evaluation reliability

Whether original scoring, failure attribution and judge behavior can be trusted.

Keep judgment in a reviewable record

A quality system connects rules, actions, rationales and adjudication instead of leaving only a final score.

01 / DERIVATION EVIDENCE

A difficult prompt is not automatically a valid task

Independent solves, answer uniqueness, reference derivations, verifiers and model calibration establish task validity.

02 / PROCESS EVIDENCE

A correct outcome does not prove a reliable process

Critical decisions, tool calls, observations, recovery and corrections enter node-level review.

03 / RUNTIME EVIDENCE

Engineering conclusions must survive environment verification

Patches, tests, logs, verifiers and reruns support the ruling together.

Security, confidentiality, access and retention requirements are agreed before production and implemented as project controls.
